# 稳定识别黑线后自动发车

不再需要发车按键。初始化完成后，默认模式为两圈循迹 `APP_MODE_LAPS`。
仅在 `APP_WAIT_START` 且已布防时，以下条件同时连续满足 200 ms 才进入 `APP_FOLLOW_LINE`：

- 循迹模块识别为 `LINE_TRACK_STATUS_NORMAL` 且控制输出有效；全白、全黑、搜索或故障均不计。
- 选择的任务模式有效。

任一条件中断、模式改变，或主循环轮询间隔超过 50 ms，重新计时。
超声波不是发车硬条件；有效的新鲜距离只在障碍检测和停车阶段参与安全判断。
`AppInputs.line_start_ready` 与运行中的 `line_valid` 分开，避免把搜索过程误当成起跑条件。
200 ms 使用无符号毫秒差计算，支持系统计时回绕，不阻塞主循环。

## 停车与重新布防

正常障碍等待仍按原规则：距离大于 100 mm 且数据有效后继续循迹。
循迹丢线故障在重新识别正常黑线后自动清除，并重新经过 200 ms 稳定确认。
停车、传感器和入库故障仍保持锁定；任务完成或手动停止也不会自动重启。

当前没有已确认接线的物理停止按键，因此提供主循环处理的调试命令：

| VS Code Watch 中的全局变量 | 操作 |
|---|---|
| `g_app_control_request = 1` | 停止并取消自动发车布防 |
| `g_app_control_request = 2` | 先停止，再重新布防；需重新满足 200 ms 起跑条件 |
| `g_app_selected_mode = 0` | 两圈循迹，默认模式 |
| `g_app_selected_mode = 1` | 侧方停车模式；视觉及停车轨迹仍待实现 |
| `g_app_selected_mode = 2` | 倒车入库模式；视觉及停车轨迹仍待实现 |

请求被处理后自动清零；停止输入优先于重新布防。重新布防可以取消正在进行的任务，
但不会在该次循环立即发车。完成后的旧时间/计数保留到下一次实际发车时才清零。
程序暂停时不会处理调试命令，需恢复执行；调试命令不是独立硬件急停。
物理停止按键后续可接入 `AppInputs.stop_pressed`，无需改状态机。
复位/重新上电会重新布防，放在黑线上时会再次自动发车。

`AppStatus` 中 `auto_start_armed` 和 `start_stable_ms` 可用于调试起跑状态。
目前 HMI 页面尚未显示启动进度，也不提供实体模式选择按键。

## 实车边界

- 循迹参数已于 2026-10-29 更新：直线基准 650/1000（65% PWM），运行范围
  当前直接修正范围为 45%～77%；原始探头电平变化后立即使用
  450/700 内侧差速或 450/770 外侧差速，
  实车探头顺序为 SW2、SW1、SW3、SW4。参数与调试步骤见 [LINE_FOLLOW.md](LINE_FOLLOW.md)。
- 空旷无反射目标时 HC-SR04 可能无回波；无回波按障碍信息无效处理，但不阻止
  发车或循迹。停车阶段仍要求有效测距。
- A/B/C/D 位置事件尚未接入真实识别，因此虽有两圈完成后的锁定逻辑，
  当前实车不会仅靠此改动自动识别 A 点、完成两圈停车。需保留人工停止手段。
- 首次烧录后先架空车轮，验证识别黑线、离线不发车、障碍阻挡、停止/重新布防、
  左右方向与电源。云端没有连接实物，未执行实机验证或烧录。

## 验证

`tests/test_app.c` 覆盖精确 200 ms 门限、信号中断、全白/全黑等非正常线型、
无超声波发车、超声波近距障碍、轮询断档、模式切换、终点/故障锁定、
循迹丢线自动恢复、停止优先、显式重新布防，以及毫秒回绕。现有两圈、
障碍和停车场景继续测试。
修改 `APP_AUTO_START_STABLE_MS` 可调整起跑稳定时间。
