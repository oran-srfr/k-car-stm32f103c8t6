# 四路循迹：低速差速与 R60 半圆

## 已确认的方向与接线

2026-10-29 用户最终确认：**探头从左到右 SW2、SW1、SW3、SW4**，
且 **SW1→X1、SW2→X2、SW3→X3、SW4→X4**。
板上接线口从左到右 X4、X3、X2、X1。接线口位置不能直接当作探头空间位置。
因此软件从左到右映射为 **X2、X1、X3、X4**，与原映射一致。
原映射不是本次确认出的反向转向原因；电机前进极性仍需实车核对。
差速公式为：黑线在右侧 → 左轮快、右轮慢；黑线在左侧 → 左轮慢、右轮快。

| 位置 | 探头 | 已确认输出口 | MCU 引脚 | 权重 | 单探头压黑线的 raw_bits（低有效） |
|---|---|---|---|---|---|
| 左外 | SW2 | X2 | PB1 | -3 | `0x0D` |
| 左内 | SW1 | X1 | PB0 | -1 | `0x0E` |
| 右内 | SW3 | X3 | PB10 | +1 | `0x0B` |
| 右外 | SW4 | X4 | PB11 | +3 | `0x07` |

默认映射下居中两内探头为 `raw_bits=0x0A`，归一化 `black_bits=0x06`。
新增 Watch 变量 `g_tracking_raw_bits` 是重排前的原始电平：bit0=X1/PB0，
bit1=X2/PB1，bit2=X3/PB10，bit3=X4/PB11，可用逐个遮挡探头确认对应关系。
`line_track.h` 中的 `LINE_SENSOR_*_BIT` 配置空间位置；四个位必须互不重复。
默认黑线低电平，若实测相反才修改 `LINE_SENSOR_BLACK_ACTIVE_LOW`。

| 电机信号 | 引脚 |
|---|---|
| 左 PWMB | PA6 / TIM3_CH1 |
| 左 BIN1 / BIN2 | PB7 / PB8 |
| 右 PWMA | PA7 / TIM3_CH2 |
| 右 AIN1 / AIN2 | PB6 / PB5 |
| STBY | 硬接 3.3 V，不占 MCU 引脚 |

逻辑正命令必须使对应车轮朝车头方向滚动。若单轮方向不符，只修改
`motor_driver.h` 中该轮的 `MOTOR_DRIVER_*_REVERSED`；不要把左右传感器再次互换。
电机极性没有从视频独立验证，本次不猜测修改。

## 连续差速控制

生产固件按 5 ms 控制周期运行同一套 PD + 恢复状态机。
移除单轮 0、另一轮 800 的硬切换模式，避免内外探头切换时反向摆头。
左内、左外都产生向左修正；右内、右外都产生向右修正，只是强度不同。
所有前进命令均经过同一个 55%～80% 混合器，停止和故障保持 0。

转向修正使用变化率限制：同方向每 5 ms 最多变化 20（单轮 2 个占空比百分点）。
例如从居中切换到左内探头，首次逻辑命令约为左 610 / 右 650；
持续检测后收敛到约 590 / 670，而不是突然停住一轮。
发现黑线换到另一侧时，先清除旧方向修正，再从零向新方向渐增，
所以不会为了平滑继续朝旧方向转；这个跨侧动作不受同方向变化率上限约束。

仓库当前 `MOTOR_DRIVER_SWAP_LEFT_RIGHT=1` 保持不变：混合器输出的左/右是
**逻辑车轮**；驱动末端按这个接线适配交换通道。
`g_left_target_command` / `g_right_target_command` 观察逻辑目标；
`g_motor_driver_left_actual` / `g_motor_driver_right_actual` 及屏幕 A 行表示
交换后的驱动通道命令，不应直接当作物理左右轮标签。实际转向应以上车核对为准。

## 占空比与差速

用户确认的 50～80 是**百分比**。驱动仍使用 1000 为满量程，
例如命令 650 ≈ 65% 占空比；定时器比较值为 `command * ARR / 1000`，
当前 ARR=3599，650 对应 CCR=2339。不要把 65 直接作为驱动命令，那只有约 6.5%。

`control_config.h` 的起始参数如下（需要实车调试）：

| 参数 | 命令值 | 对应意义 |
|---|---|---|
| 直线基准 | 650 | 65% |
| 普通弯基准 | 630 | 63% |
| 大偏差弯基准 | 620 | 62% |
| 找线基准 | 650 | 65% |
| 两轮运行下限 | 550 | 55%，相对 50% 留 5 个百分点余量 |
| 两轮运行上限 | 800 | 80% |
| Kp / Kd | 40 / 0.2 | 内探头小修正，外探头增大差速 |
| 修正限幅 | 120 | 单轮最多 ±12 个百分点 |
| 静态差速补偿 | 0 | 正数提高左轮、降低右轮；10 = 单轮 1 个百分点 |
| 微分低通时间常数 | 30 ms | 滤波系数随控制周期换算 |
| 转向变化率 | 4000 命令单位/秒 | 5 ms 周期对应单轮每次 2 个百分点 |

混合器先限制差速，再调整两轮共同基准，保证两轮始终在 55%～80% 范围内，
不让内轮掉入死区或反转。比如强右修正 120 时得到左 790 / 右 550。
因此表中的弯道基准不是最终平均占空比的硬上限：转向需求大时，为保留差速且
不让内轮停转，平均占空比可能上移。停车、故障及输出门控关闭仍是两轮 0。
如 55% 在地面负载下仍不起转，应先测实际死区，再在 80% 上限内调整下限；
软件无法仅凭一个范围保证每台电机都克服静摩擦。

微分项使用 30 ms 时间常数的低通，并限制为 ±30（单轮 ±3 个占空比百分点），
减少数字探头跳变对差速的冲击。静态差速补偿仍可通过
`s_motor_command_config.straight_trim` 微调（建议每次 ±5）。
目前没有编码器速度闭环，PWM 相同不代表转速相同。

## 半圆与丢线恢复

赛道依据用户提供的图以及仓库 `_k_figs/image11.png`：AB、CD 长 85 cm，
B–C 半圆半径 60 cm，AD 长 120 cm。半圆采用每 5 ms 一次的在线差速反馈，
不按固定时间转 180°，也不以“偏差为 0”判定已经驶出圆弧。

- 偏差增大时切换弯道基准；短暂居中后保持弯道速度 40 个周期（200 ms），
  避免弧上反复加速。持续居中后，基准每周期最多增加 5（0.5 个百分点）。
- 短暂居中保留最近转向；连续居中 200 ms 后清除旧方向，防止驶入直线后
  的偶发丢线又沿上一个弯的方向急转。短暂丢线沿仍有效的最近方向渐增差速，
  无方向时保持直行；起步无有效历史且丢线则停车。
- 重新找到线后，只平滑基础速度，差速目标立即使用当前偏差，并按上述规则渐变；不再把旧的左右轮
  命令混入新方向，避免线已出现在另一侧时继续朝旧方向转。
- 默认需要连续 20 个有效周期（100 ms）确认找回。确认前累计丢线预算不清零，偶发单次
  检出不会无限延长搜索。累计超过 60 个丢线周期（300 ms）后锁存故障、输出零。
- 所有持续时间从毫秒换算成周期数，避免控制频率改变时延时意外减半。
- 全黑仍进入故障并输出零。A/D 的直角、交叉线、宽线等需要单独的赛道事件设计，
  本次 R60 验证不代表已经实现完整赛道自动跑圈。

## 上车核对顺序

1. 架空车轮，分别遮挡四个探头，核对上表 `raw_bits`、偏差符号与实际前进方向。
   单左探头压线时应右轮更快，单右探头压线时应左轮更快。
2. 在地面确认 55% 能持续驱动两轮；先测试直线，观察 `g_tracking_deviation`、
   `g_left_applied_command`、`g_right_applied_command`。仍摆头时优先降低 Kp，
   有固定偏航时小步调整 `straight_trim`，每次只改一个参数。
3. 测试 AB → B–C 半圆 → CD，确认入弯、弧中短暂居中、出弯都向前。
   必须按实际轮距、传感器间距、探头距轮轴距离及黑线宽度调参。
4. 测试短暂离线后恢复，以及持续离线超时停车。当前应用层保留主分支的丢线
   故障自动恢复：重新看到正常线型后，需重新满足 200 ms 自动发车条件。
   完成/手动停后按 [AUTO_START.md](AUTO_START.md) 的 `g_app_control_request=2` 重新布防。

自动启动只要求正常线型连续 200 ms；超声波无效不再阻止起跑或循迹。
有效且新鲜的近距障碍仍会触发障碍等待，失去回波只代表障碍信息不可用。

## 验证与边界

Windows：`tests/run_tests.ps1`；Linux：`sh tests/run_tests.sh`。
`test_line_follow` 使用与生产固件相同的默认编译配置，覆盖单内侧抖动、
同侧内外探头过渡、跨侧转向、55%～80% 限幅、丢线预算、方向记忆过期、
200/100/300 ms 时间语义和 R60 运动学模型。测试不再通过宏切换到另一套控制算法。

R60 模型覆盖 AB→半圆→CD 的顺/逆时针、左轮响应 ±3%，以及 ±5% 响应差异
叠加 50 ms 电机惯性和每 355 ms 一次的 5 ms 丢线，共 10 个场景。
模型假设轮距 14 cm、探头前置 8 cm、间距 1 cm、线宽 15 mm、轮速=0.6×占空比 m/s；
这些不是已测实车数据，也没有模拟轮胎打滑、真实电机死区或供电变化。
它验证控制器的逻辑左右轮，物理通道交换是否匹配实车仍需核对。
模型通过不等于实车已经通过半圆，本次没有烧录或实车验证。

视觉、编码器速度闭环、停车轨迹、A/B/C/D 真实位置识别仍未实现。
